# Dashboard 开发与扩展

UsageMesh Dashboard 是纯静态 React 应用。已有设备、原 Dashboard 密码、GitHub 数据分支和 CLI 工作方式保持兼容。部署到 GitHub Pages 后可直接使用，无需新增服务器、数据库或第三方账号。

## 本地运行

使用 Node.js 22 或更新版本：

```bash
cd web-ui
npm ci
npm run dev
```

打开终端输出的网址。默认读取 `Atingaii/UsageMesh`；读取自己的工作区可使用 `http://127.0.0.1:5173/?repo=OWNER/REPO`。输入该工作区原来的 Dashboard 密码。只需要读取公开的加密账本，不要在网页中提供 GitHub PAT。

生产构建验证：

```bash
npm run typecheck
npm test
npm run format:check
npm run build
npm run preview
```

GitHub Pages 使用相对资源路径，支持 Fork 改名。分区导航使用 hash，直接访问 `#analytics`、`#aggregated`、`#devices`、`#settings` 不依赖服务端路由规则。

## 界面和可用功能

- **用量概览**：总 Tokens、设备端费用估算、请求数、缓存命中率；八种趋势指标；Token 构成和模型、客户端、设备、路由分布。
- **分析工作台**：结构效率、八维度贡献分析、近期请求、设备 × 模型矩阵、高消耗组合。Top 3 占比按全部筛选记录计算，不因图表只展示前 14 项而夸大。
- **数据明细**：可聚焦排序、全文搜索、25/50/100 条分页、完整字段切换和记录详情。CSV 导出当前筛选和搜索匹配的全部记录，包含定价状态、设备 ID 和毫秒时间戳；不是只导出当前页。
- **设备管理**：平台、架构、CLI 版本、账本更新时间与心跳分开展示；设备搜索、状态筛选、接入指引、同步诊断和跳转设备用量。
- **工作区设置**：浅色/深色/跟随系统，10/30/60 秒或手动刷新，每月本地费用提醒，以及部署版本信息。
- **保存视图**：每个仓库可以在当前浏览器保存一组筛选，并显式恢复或删除；不写入 URL，也不上传 GitHub。

日期筛选优先使用时间戳对应的浏览器本地时间。“自定义”包含所选结束分钟的最后一毫秒，逆序或不完整范围会提示修正。只有日期的旧账本仍按其记录日期回退。

请求数据受设备账本自身的滚动保留范围限制。前端不再施加额外 300/5000 条截断，但不能凭空恢复设备已经淘汰的历史请求。聚合账本与近期请求不必有相同记录数量。

月度费用提醒基于本月已读取的全部设备，不受页面筛选影响；只是兼容价卡估算的界面提示，不发送通知、不限制额度、不代表供应商账单。部分设备读取失败时界面会明确标记总量不完整；未解析完整价卡的数据传播“≥”费用下界标识。

## 设计基线

对齐 GrowthOS-Go 的 `docs/frontend/frontend-ui-baseline.md` 和 `web/src/index.css`：

- white/zinc 中性色、`#625df5` 主色，暗色 `#7c74ff`；绿色/琥珀色/红色表达独立状态；
- 本机 Inter / 系统中文字体与 SFMono 回退，无远程字体请求；
- 细边框、约 10px 圆角、轻阴影和有节制的留白；
- 解锁页面采用左侧叙述、右侧主任务卡；工作台采用共享侧边导航和内容区域；
- 移动端使用原生 dialog 导航和弹窗，保留焦点边界与 Escape 退出；可见焦点、语义标签、文字状态、触控尺寸及 reduced-motion 同时参与可访问性。

保留 UsageMesh 自有产品身份，不复制 GrowthOS 业务页面或权限模型。

## 模块边界

| 路径 | 职责 / 扩展点 |
| --- | --- |
| `src/lib/types.ts` | 统一领域类型；新字段先在这里定义 |
| `src/lib/data.ts` | 仓库解析、索引、PBKDF2/AES-GCM、账本适配、设备状态、部分失败 |
| `src/lib/session.ts` | 当前标签页的加密会话、IndexedDB 包装密钥、过期和锁定 |
| `src/lib/analytics.ts` | 日期范围、筛选、指标/维度注册、统计、CSV 编码 |
| `src/lib/preferences.ts` | 有版本的本地偏好；存储不可用时安全回退 |
| `src/hooks/useDashboard.ts` | 解锁、刷新互斥、会话生命周期和异步结果归属 |
| `src/components` | 工作台外壳、筛选、通用表格、解锁与接入界面 |
| `src/views` | 概览、分析、设备、设置；按需加载 |
| `src/app.tsx` | 页面组合、导航、共享筛选和偏好 |
| `tests` | 真实加密夹具、时间/费用/导出/并发/表格回归测试 |

新增客户端应在 CLI 的采集/适配层输出现有账本字段，前端会自动发现客户端、模型与路由维度，不需要硬编码新的选择列表。新增指标通常只需扩展领域类型、适配层和 `METRICS`，再按需要补充展示。

后续有价值但未在本次引入的能力：设备端可配置请求留存、数据质量诊断摘要、账本增量下载与解密缓存。它们需要协议/采集端配合，不应仅在前端做空操作入口。远程告警、团队权限、多租户等需要新的服务边界，应单独设计。

## 安全与可靠性

- 费用直接来自设备逐请求计算后的账本；前端不下载价格表并重新定价聚合记录。
- 旧版 310,000 次和新版 600,000 次 PBKDF2 均由真实 WebCrypto 测试覆盖；拒绝越界 KDF 参数及设备哈希/分支不匹配。
- 密码不持久化；工作区密钥只以密文存入当前标签页的 sessionStorage，不可导出的包装密钥存 IndexedDB。
- 同标签刷新可以恢复；闲置 30 分钟、12 小时绝对期限和手动锁定生效。无法持久化时仍提供仅内存会话，并保留过期机制。
- 刷新请求互斥，网络读取有 20 秒超时；失败保留上次快照并显示失败状态，部分设备失败不会伪装成全部同步成功。
- 手动锁定/过期使进行中请求失去发布资格，晚到响应不能重新显示数据。
- 导出保留中文 UTF-8 BOM，并转义 CSV 结构和公式前缀。导出文件包含用户已解密的用量元数据，请按自己的数据管理方式保存。
- 维持严格 CSP、`no-referrer` 和静态部署；CI 改用行为测试校验拆分后的实现。

## 浏览器验收夹具

`tests/browser-fixture.mjs` 生成独立的合成加密账本，使用随机工作区密钥和测试专用密码：

```bash
node tests/browser-fixture.mjs /tmp/usagemesh-browser-fixture.json
```

输出只供浏览器网络拦截使用：将 `responses` 的各路径映射到 `https://raw.githubusercontent.com/fixture/UsageMesh/<path>`，打开 `?repo=fixture/UsageMesh` 并使用夹具内的测试密码。应通过正常输入、解密、会话恢复和渲染流程验收，不在应用中加入跳过解锁的测试开关。该文件不被产品代码导入，不进入生产包。验收后删除生成的 JSON 和浏览器临时文件。

## 阅读体验与扩展路线（2026-09-07）

全站字号改用 rem，主体文字 14–16px，表格/辅助信息 12–14px，手机不再缩小到 9–10px。优先使用系统 UI 字体，统计数字使用等宽数字特性，代码和标识符仍用等宽字体。工作区设置提供标准和大字（112.5%）阅读，浏览器本地保存；旧偏好自动兼容，浏览器自身缩放仍可使用。

建议后续按以下顺序扩展，不把规划中的功能展示成可用入口：

1. **多组命名视图**：将当前每仓库单个保存视图升级为命名列表，支持重命名、删除及旧视图迁移。适合按设备、项目和模型反复排查，纯前端即可闭环。
2. **上一周期对比**：对等长完整周期计算 Token、费用和请求变化，明确时区、当前未结束周期和前期为零的情况。先提供本地分析，不改写设备端费用真值。
3. **数据质量摘要**：汇总缺失账本、心跳滞后、定价兜底占比与请求留存覆盖范围。缺失字段需要采集端提供证据，不能把“无数据”显示为“零消耗”。
4. **增量同步与缓存**：按设备账本版本复用解密结果；需要处理锁定清理、版本失效及多设备更新一致性，适合历史数据变大后实施。

远程告警与团队权限涉及持续运行服务和授权边界，暂不作为静态面板的小改动加入。
