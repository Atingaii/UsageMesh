# 全站工作台重构验收 · 2026-09-10

本目录截图全部来自明确标注的模拟工作区。没有用户密码、解密密钥、真实账本或用户截图。运行 `npm --prefix web-ui run dev -- --port 4178`，打开 `/qa/subscriptions.html?shell&tab=overview`。生产构建不包含 QA 页面。

## 设计依据与改动

- [CodexBar 实际额度行模型](https://github.com/steipete/CodexBar/blob/main/Sources/CodexBar/MenuCardView.swift)与[官方 UI 说明](https://github.com/steipete/CodexBar/blob/main/docs/ui.md)：同账号先展示多个额度行，成本信息置于次级区域。
- [onWatch 实际账号卡模板](https://github.com/onllm-dev/onWatch/blob/main/internal/web/static/menubar.html)：provider / 账号内渲染多种额度，避免将每一个窗口当成独立订阅。
- [ccusage 周期报告实现](https://github.com/ccusage/ccusage/blob/main/rust/crates/ccusage/src/blocks.rs)：成本作为报告字段，预测附属于活动周期。本项目继续使用用户指定的「已用金额 ÷ 已用额度百分点 × 100」，未照搬其时间投影算法。
- 整体视觉延续用户提供的 LINUX DO Credit 截图方向：浅色底、白色内容面、细边线、紫色重点。使用 216px 侧栏、56px 工具栏与至多 1280px 的内容区，统一字号、间距、表格与筛选。

概览以四项汇总与整行趋势为主，分析的巨大百分比卡改成行内摘要。设备以表格比较心跳、账本、版本和用量。常用设备/客户端/模型筛选常显，额外维度与保存视图可展开。概览底部周期对比与数据诊断按需挂载。设置按外观/刷新/提醒与信息/隐私分栏，指南复用全站标题。

订阅页将同账号主额度同时列出，Spark 等附加额度默认折叠；多账号才出现账号选择，多个主窗口才出现统计周期选择。金额与 Tokens / 请求组成紧凑汇总，公式和排名进入详情。历史仍以真正到期的窗口为单位，已退出账号的历史保留可访问；不把内部改期片段当成历史周期。未计价、设备落后、低比例估算的必要限制保持首屏可见。

## 正确性与性能

完整测试集 148 项通过，TypeScript、Prettier、生产构建与 `git diff --check` 通过。回归包括账号/窗口隔离、重置漂移、改期归档、历史账号访问、公式截止时间、0%/过期/未计价保护、分页搜索导出、筛选状态保留、设置与模拟锁定解锁。

5 万条模拟记录的本机开发模式 React Profiler 单次采样：订阅首屏31.1ms，切换历史0.7ms，打开分页账本40.1ms，账本仅渲染每页25条。控制台未见 error/warn。这些是 React 渲染工作时长，不能当成网络加载、用户交互延迟或生产性能保证。

刷新现在并行读取每台设备的账本和心跳，减少同一设备的串行等待。完整聚合账本不会被最近1000条请求明细替代。独立合成网络测试和生产只读核对的限制见[性能记录](../../FRONTEND-PERFORMANCE.md)。

生产页曾在刷新中显示较小金额；此后自动刷新恢复完整多模型记录。核查时本机、GitHub REST、raw 密文解密后及实际前端加载结果一致。本轮未保留当时旧响应，因此不能断言早先差异的唯一原因，也不宣称修复了历史丢账。

本轮重构覆盖云端 Dashboard；本地管理服务仍为独立入口。未改变原始账本、官方采样或采集算法，未新增反向代理。

## 发布回归补充 · 2026-09-11

第一次上线后在真实工作区观察到一次刷新 6/6 设备成功、下一次刷新 4/6，订阅区域随之消失。代码确认原先的 `Promise.allSettled` 只把本轮成功设备放进数据集，暂时失败的设备即使已经成功读过，也会被移出本次汇总。这是本轮实际复现并修复的问题，不据此追溯认定所有早先金额变化的唯一原因。

现在对同一标签页解锁会话、同一仓库和密钥下的临时网络错误、超时及 HTTP 408/429/5xx，沿用该设备上次完整构建成功的快照。账本、心跳和官方观测时间保持原值，顶栏、设备页和订阅估算同时标明未更新；「最近检查」不再写成「最近成功检查」。认证、404、格式、AAD 和解密错误不使用设备回退；首次读取无成功缓存时仍提示数据未齐。缓存仅在内存，锁定重建；从索引移除的设备不复活，跨仓库/密钥和旧在途请求不能污染缓存。

新增回归覆盖连续失败→恢复、混合成功/首次失败、错误类别、原始时间和账本/官方数据引用保持、异常数据不覆盖成功缓存及跨作用域隔离。浏览器验证的是明确标注的模拟故障/恢复状态，真实加载器的网络分支由上述单元测试验证。

最终线上回归还确认了采集顺序导致的秒级误判：扫描先写账本生成时间，再拉官方额度，同一分钟内相差数秒也可能触发等待。现将同步判断与金额口径统一到官方观测前最后一个已结束分钟；同分钟先扫描、后观测可估算，跨分钟未覆盖、非对齐桶及未来消费继续排除。测试明确覆盖这两类边界，未改变采集时间或官方观测时间。
