# 解锁超时修复验收 · 2026-09-11

## 确认的问题

用户截图显示「数据读取超时」，不能据此认定密码错误。原登录流程依次执行访问配置读取、密码解密、索引和设备账本加载；任一步失败都会回到密码页。表单请求前清空密码，任意错误都给密码框标红；恢复的有效会话也会因数据读取失败被清掉。

公开访问配置的本机只读探测当时 RAW 为 200 / 0.624s，GitHub Contents API 为 200 / 0.633s。没有留存截图发生时的网络响应，不能断言当时哪一个文件或网络节点超时。

## 修复

- 正常情况仍只读 RAW。单文件 RAW 暂时失败或 8 秒超时后，尝试一次 [GitHub 官方 Contents API 的 raw media](https://docs.github.com/en/rest/repos/contents#get-repository-content)，该备用请求最多 12 秒。只对网络、超时、408、429、5xx 使用备用；401/403/404、JSON、包络、AAD 与解密错误不借备用路径掩盖。
- 同步更新 CSP，只新增官方 `api.github.com` 连接域名。请求只携带公开仓库路径和媒体类型，不发送密码、解密密钥、Cookie 或本机令牌。两条官方路径都失败时仍明确显示错误，不无限重试。
- 密码验证与账本读取分开。访问配置尚未读取成功时保留用户输入；只有实际密码解密失败才标红。密码已验证后移除密码输入，数据失败可以直接「重新读取数据」，无需重复验证。
- 已验证但尚未加载成功的会话也受闲置30分钟、绝对12小时限制。加密会话保存/删除串行，锁定后晚到结果不能恢复会话。
- 索引的网络失败保留网络原因，不再一律引导执行设备初始化。仓库标识禁止自动翻译，隐藏用户名字段使用 `type=hidden`。

`npm --prefix web-ui test`：179 项通过。TypeScript、Prettier、生产构建与 `git diff --check` 通过。

新增 `web-ui/qa/unlock.html` 为开发专用入口，采用真实 `useDashboard`、`UnlockScreen`、PBKDF2/AES-GCM 解密与加密会话存储。仅使用明确标记的模拟数据和公开演示密码 `demo`，拦截该页全部网络请求；不包含在生产构建中，不连接真实工作区，也不跳过认证。

本机以独立端口4183验证（`npm --prefix web-ui run dev -- --port 4183 --strictPort`）：

- `?scenario=access-timeout`：配置的主/备用请求首次均超时，密码框不标红；不重新输入、直接再次点击解锁，成功读到1台演示设备/1条用量。390×844手机视口下，实际宽度与scrollWidth均为384，没有整页横向溢出。
- `?scenario=data-timeout`：实际验证密码后首次账本读取超时，页面显示「工作区已验证」和「重新读取数据」，不再显示密码输入；点击重试成功进入工作区。
- `?scenario=raw-unavailable`：主地址始终失败，官方API模拟响应可完成真实解密。错误密码显示密码错误，改为正确演示密码后成功加载。

单元/集成回归还覆盖8+12秒截止、永久错误不回退、无API的正常路径、CSP允许实际备用请求、恢复有效会话后读取失败、同一密码不重复验证、重复提交、锁定期间晚到认证/保存/读取及待重试状态自动过期。浏览器控制台未见应用错误。

验收未读取用户密码、本地凭证或真实账本明文；没有替用户输入真实密码。模拟会话经锁定清除，临时页面、开发服务及验证构建目录在交付前清理。
