# 紧凑界面删减验收 · 2026-09-11

这轮目标是减少信息重复与操作层级。沿用现有 React、样式变量和数据层，没有新增依赖或数据源。

## 对照与实际删除

参考 CodexBar 的 [UI 规范](https://github.com/steipete/CodexBar/blob/main/docs/ui.md)、[MenuCardView](https://github.com/steipete/CodexBar/blob/main/Sources/CodexBar/MenuCardView.swift)，以及 onWatch 的 [紧凑额度行](https://github.com/onllm-dev/onWatch/blob/main/internal/web/static/menubar.html)。CodexBar 官网截图读取失败，参考依据是已核验的官网文本与开源实现，不把源码研究写成截图验收。

- 订阅由“视图标签 → 额度大面板 → 周期下拉 → 用量大面板 → 公式/双排名”收敛成一个账号面板。直接点击主额度行切换用量，默认最长窗口。
- 每行仅显示一个剩余比例、进度条及同窗口重置时间。绝对时间对触屏用户同样可见；快照过期、提前耗尽仍显示。
- 金额改为连续键值行，总金额估算与公式首屏可见。Tokens/请求/设备合并为一行，统计口径按需挂载。
- 删除订阅页设备/模型排名；删除概览页模型/客户端/设备/路由四组排名，分析工作台保留详细分析。未启用的预算提醒推广条删除。
- 删除侧栏工作区头像、分类标题、重复帮助入口、顶栏页面面包屑及品牌页脚。仓库身份只显示一次，保留全部导航、刷新、主题、锁定、接入设备和费用口径。

## 正确性与交互

`npm test`：18 个文件、184 项测试通过；`typecheck`、`format:check`、生产 `build`、`git diff --check` 全通过。

关键回归：

- 同一真实窗口的比例、重置时间、账本与金额一起切换。周 $570 / 57% = $1,000；5 小时 $100 / 25% = $400；窗口外消费不会混入 5 小时金额。
- 官方观测前完整分钟截止、零用量、过期、多账号、额度调整、账本落后与部分设备沿用快照保护全部保留。
- 真正到期周期归档；Spark 历史只显示其官方观测，不挪用整个工作区的金额、Tokens 或 CSV。
- 全站导航、移动菜单、锁定/解锁、网络超时恢复、筛选、账本分页/导出及预算提醒语义均通过回归测试。

浏览器实际操作：桌面主窗口来回切换；390px 手机布局、深浅主题切换、导航打开/关闭、历史列表进入详情和导出按钮可达。手机 iframe 内 `clientWidth = scrollWidth = 390`，当前与历史详情均无横向溢出。浏览器尺寸覆盖未作用于已有隐藏标签，手机使用临时 iframe 装载同一个真实 QA 页面验证，未替换任何产品组件；临时页面交付前删除。

保留 memo、账本缓存、统计口径按需挂载和表格分页。本轮删除了重复渲染内容，但没有新增网络性能宣称或用模拟数据证明真实同步耗时。
